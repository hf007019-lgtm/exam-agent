# Exam Agent 项目概览

## 项目背景

招考选岗往往同时涉及职位表筛选、资格条件核对、历史分数理解、报名数据判断和政策术语解释。传统表格查询只能回答“有哪些记录”，很难帮助用户形成可复核的决策过程。

Exam Agent 将结构化招考数据与 AI 对话结合，定位为“面向招考数据的 AI 决策分析工作台”。它不替代官方公告和资格审查，而是帮助用户更快完成初筛、比较、风险识别和信息缺口确认。

## 解决的问题

- 根据学历、专业、身份和地区条件找到可关注岗位。
- 精确查询单个职位，并解释报考限制与已知风险。
- 区分岗位精确历史分数、同类参考和无匹配状态。
- 在报名人数、缴费人数、竞争比或分数缺失时明确数据不足。
- 解释政策术语，并在无可核验来源时清楚降级。
- 将画像、备选、对比和分析记录组织成连续的选岗工作流。

## 核心模块

- `app/agents`：意图判断、Prompt 构建、多轮上下文和 Agent 编排。
- `app/tools`：岗位、分数、政策、风险和数据目录工具。
- `app/imports`：Excel/CSV 读取、表头识别、字段映射、清洗和报告结构。
- `app/services`：导入、LLM、RAG、认证和产品服务。
- `app/db`：SQLite 初始化、仓储和导入数据持久化。
- `app/api`：Agent、导入、用户、会话、收藏和报告 API。
- `app/static`：九个一级页面组成的 Web 工作台。

政策资料检索由外部服务通过 HTTP 提供。本项目不包含 PDF 解析、对象存储、任务队列、向量索引或知识库运维实现。

## 技术栈

- Python、FastAPI、Pydantic
- SQLite
- pandas、openpyxl、xlrd
- OpenAI-compatible API
- 原生 HTML、CSS、JavaScript

## 设计原则

1. LLM 负责理解和解释，代码负责数量、年份、省份、匹配类型和缺失状态。
2. 结构化工具结果是事实源，AI 不补写报名人数、竞争比或分数。
3. 推荐是初筛，历史数据是参考，不输出录取概率和绝对化结论。
4. 普通用户界面不暴露内部文件名、磁盘路径、模型名或 debug 字段。
5. 姓名、准考证号等敏感信息默认隐藏，不进入 Agent 分析上下文。
